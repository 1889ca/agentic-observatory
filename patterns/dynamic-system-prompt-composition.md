# Dynamic System Prompt Composition

> Runtime assembly of system prompts from persona, capabilities, behavioral rules, and contextual signals.

## Problem

A static system prompt becomes stale as the orchestrator evolves. New capabilities, learned anti-patterns, user preferences, and situational context all need to influence how the LLM behaves — but a monolithic prompt file can't adapt at runtime. Manually updating it for every new tool, persona shift, or behavioral correction doesn't scale and introduces drift between what the prompt says and what the system actually does.

## Context

- An orchestrator with a growing set of capabilities, plugins, and integrations
- Persona and behavioral guidelines that evolve based on user feedback
- Anti-patterns learned from operational mistakes that should prevent recurrence
- Different conversation contexts (user chat, autonomous task, reflection) requiring different prompt framing
- Skill descriptions that should appear in the prompt only when relevant
- User profiles with per-user preferences and interaction history

## Solution

### Prompt Composition Pipeline

The system prompt is assembled at dispatch time from multiple sources:

```
Persona → Behavioral Guidelines → Capability Manifest →
Anti-Patterns → Skill Descriptions → Vibe Detection →
User Profile → Final Prompt
```

Each section is generated by a dedicated builder function, and the results are concatenated into the final system prompt.

### Persona Layer

The base personality and role definition:

```javascript
function buildPersona(context) {
  const base = personas.get(context.personaId || 'default');

  return `# Identity
${base.name} — ${base.role}

# Core Traits
${base.traits.map(t => `- ${t}`).join('\n')}

# Communication Style
${base.style}`;
}
```

### Behavioral Guidelines

Rules extracted from operational experience and user corrections:

```javascript
async function buildGuidelines() {
  const rules = await guidelines.getActive();

  return `# Behavioral Guidelines
${rules.map(r => `- ${r.rule} (learned: ${r.learnedFrom})`).join('\n')}`;
}
```

These accumulate over time. When the LLM makes a mistake and gets corrected, the correction is stored as a guideline that prevents recurrence.

### Capability Manifest Injection

Rather than listing all 225+ tools in the system prompt, inject a summary of capability categories:

```javascript
function buildCapabilitySummary() {
  const categories = toolRegistry.getCategories();

  return `# Available Capabilities
${categories.map(c =>
  `## ${c.name} (${c.tools.length} tools)\n${c.description}`
).join('\n\n')}

Individual tool schemas are provided separately via function declarations.`;
}
```

### Anti-Pattern Section

Learned mistakes that should be explicitly avoided:

```javascript
async function buildAntiPatterns() {
  const patterns = await antiPatterns.getActive();
  if (patterns.length === 0) return '';

  return `# Anti-Patterns (DO NOT)
${patterns.map(p => `- ❌ ${p.description} → Instead: ${p.correction}`).join('\n')}`;
}
```

### Vibe Detection

Contextual tone adjustment based on the current conversation:

```javascript
function detectVibe(conversation) {
  const signals = {
    urgent: conversation.messages.some(m => m.text.match(/urgent|asap|broken|down/i)),
    technical: conversation.messages.some(m => m.text.match(/debug|error|stack|deploy/i)),
    casual: conversation.messages.some(m => m.text.match(/hey|thanks|cool|nice/i)),
  };

  if (signals.urgent) return 'Be concise and action-oriented. Skip pleasantries.';
  if (signals.technical) return 'Provide technical detail. Include code references.';
  if (signals.casual) return 'Conversational tone is appropriate.';
  return '';
}
```

### User Profile Integration

Per-user preferences that customize behavior:

```javascript
async function buildUserContext(userId) {
  const profile = await userProfiles.get(userId);
  if (!profile) return '';

  const sections = [];
  if (profile.timezone) sections.push(`User timezone: ${profile.timezone}`);
  if (profile.preferences) sections.push(`Preferences: ${profile.preferences.join(', ')}`);
  if (profile.expertise) sections.push(`Expertise level: ${profile.expertise}`);

  return `# User Context\n${sections.join('\n')}`;
}
```

### Final Assembly

```javascript
async function composeSystemPrompt(context) {
  const sections = await Promise.all([
    buildPersona(context),
    buildGuidelines(),
    buildCapabilitySummary(),
    buildAntiPatterns(),
    buildSkillDescriptions(context),
    Promise.resolve(detectVibe(context.conversation)),
    buildUserContext(context.userId)
  ]);

  // Filter empty sections and join
  return sections.filter(Boolean).join('\n\n---\n\n');
}
```

## Implications

- System prompt size grows with the number of guidelines, anti-patterns, and skills — token budget management is essential
- Stale anti-patterns waste prompt tokens — periodic review and pruning is needed
- Vibe detection is heuristic and can misread tone — false urgency detection causes terse responses when warmth is needed
- Per-user customization means the same question can produce different responses for different users — harder to debug
- Dynamic composition makes the effective prompt invisible in code review — logging the assembled prompt aids debugging
- The prompt is rebuilt on every dispatch — caching helps for the static sections but contextual sections must be fresh

## Code Example

```javascript
// Full dispatch with dynamic prompt composition
async function dispatch(message, conversation) {
  const systemPrompt = await composeSystemPrompt({
    personaId: conversation.persona,
    conversation,
    userId: message.userId,
    dispatchType: classifyMessage(message)
  });

  const response = await model.generate({
    systemInstruction: systemPrompt,
    contents: conversation.messages,
    tools: capabilities.getDeclarations()
  });

  // Log the composed prompt for observability
  await promptLog.record({
    conversationId: conversation.id,
    promptLength: systemPrompt.length,
    sections: countSections(systemPrompt),
    vibeDetected: detectVibe(conversation)
  });

  return response;
}
```
